# 支付宝正式环境配置手册

**面向上线。** 开发阶段用的是开发者的个人支付宝账号 + 内网地址；上线要换成
**部署方自己的账号**（个人或公司都行，签约路径一样）和公网地址。
本文是那条路怎么走。

> ⚠️ 开放平台的控制台界面**改版很频繁**。本文按**要做什么**来写，菜单路径会
> 注明大致的层级，对不上时按功能名找。凡是我不确定的地方都明确标了「需现场确认」。
>
> 原理与「为什么这么设计」在 [alipay-login.md](alipay-login.md)。本文只讲怎么配。

---

## 开始之前

### 这个系统用到支付宝的 **4 个能力**

它们分属**两组产品**，要分别签约。少签任何一组，对应的功能就不可用：

| 用在哪 | 走哪个接口 | 需要签的产品 |
| --- | --- | --- |
| **付款**（手机） | `alipay.trade.wap.pay` | **手机网站支付** |
| **付款**（电脑） | `alipay.trade.page.pay` | **电脑网站支付** |
| **结算/退款** | `alipay.trade.query` / `refund` / `close` | 随上面两个产品一起开通 |
| **一键登录**（顾客扫码进系统） | `alipay.system.oauth.token` | **获取会员信息** |

> 代码里还留了一条 `alipay.trade.precreate`（**当面付**），但**前端不会选它** ——
> 当面付是线下收银场景的产品，网页应用一般签不下来。**这一条不用签**。
> 详见 [alipay-login.md](alipay-login.md)。

### 🚨 生产地址必须是 HTTPS

这不是偏好，是硬要求：

| 端 | 后果 |
| --- | --- |
| **iOS** | 支付宝 iOS 客户端基于 WKWebView，**不加载 http 明文** → 授权回来那一步**白屏**。安卓/鸿蒙不受影响 |
| **PC 浏览器** | http 站点上支付、剪贴板等一堆浏览器能力会被限制 |

开发期内网用 http 是没办法，生产不行。

> 相关的另一个已知坑：授权回调地址里带 `#` 在 iOS 上可能出问题（社区反馈）。
> 若上线后 iOS 仍失败，**第一件事就是把回调地址换成不带 `#` 的路径**，
> 后端不用改。见 [alipay-login.md](alipay-login.md)。

### 需要准备什么

| 东西 | 说明 |
| --- | --- |
| **支付宝开放平台账号** | <https://open.alipay.com>，用支付宝账号直接登录 |
| **实名认证** | 个人实名账号**就能签**手机网站支付 / 电脑网站支付 / 获取会员信息 —— **实测过**（见下面的说明） |
| **公网 HTTPS 域名** | 一个就够 —— 所有门店访问的是这**同一个**地址 |
| **服务器** | 已经跑着 cups-web |

> ✅ **个人账号可以签这三个产品，不需要企业主体。** 本项目当前的开发环境就是
> 用一个**个人账号**签下了「手机网站支付 + 电脑网站支付」，走完了付款全链路。
> 公司**前期也计划先用个人账号**。
>
> 🚫 **不要再往这里写「必须企业资质」**。网上大量说法是「个人只能做沙箱」，
> 那是过时的（或者只适用于某些产品），与实测不符。真遇到签不下来的情况，
> 以开放平台控制台**当前**的提示为准，别以任何文档为准 —— 包括这一份。
>
> 本文后面的步骤对**个人账号和企业账号都一样适用** —— 签约、密钥、回调地址、
> 环境变量这些没有任何差别。两者的其它差异（结算、发票、能签的产品范围等）
> 以开放平台控制台为准，本文不做断言。

## 第一步：创建应用

开放平台控制台 → **控制台 → 应用 → 创建应用**。

- 应用类型选**网页/移动应用**（本系统是网页应用）
- 创建完记下 **AppID**（形如 `2021007xxxxxxxxx`）

> ⚠️ **一个应用只能配一个授权回调地址**。本系统的部署形态是「所有门店访问
> 同一个公网地址」，所以不构成问题。但如果将来真的要多个域名，就得建多个应用。

---

## 第二步：生成密钥对

支付宝用 **RSA2** 签名。需要一对密钥：

- **应用私钥** —— 你自己留着，配到系统里，**永远不要给任何人**
- **应用公钥** —— 上传到开放平台
- **支付宝公钥** —— 上传之后开放平台会给你，配到系统里

> 🚫 **本系统只支持「公钥模式」，不支持「证书模式」。** 证书模式需要额外
> 上传 `app_cert_sn` / `alipay_root_cert_sn`，本系统没实现。控制台上**不要**
> 选证书模式。

### 生成

用**支付宝官方提供的「支付宝密钥生成器」**（开放平台文档里能下到，Windows/Mac 都有），
或者用 OpenSSL：

```bash
# 生成 PKCS8 格式的应用私钥（RSA 2048）
openssl genrsa -out app_private_key.pem 2048
openssl pkcs8 -topk8 -inform PEM -in app_private_key.pem \
  -outform PEM -nocrypt -out app_private_key_pkcs8.pem

# 从私钥导出应用公钥
openssl rsa -in app_private_key_pkcs8.pem -pubout -out app_public_key.pem
```

### 手上会有这三样

```
app_private_key_pkcs8.pem    → 配到 ALIPAY_PRIVATE_KEY（保密！）
app_public_key.pem           → 上传到开放平台
（上传后开放平台给的）支付宝公钥 → 配到 ALIPAY_PUBLIC_KEY
```

> **配置格式很宽松**：PEM（带 `-----BEGIN-----` 头）、光秃秃一行 base64、
> 中间被编辑器插了换行 —— **三种都认**。所以直接从平台上复制粘贴就行，
> 不用手动整理格式。

---

## 第三步：上传应用公钥，拿支付宝公钥

开放平台控制台 → 你的应用 → **开发设置 → 接口加签方式** → 选「**公钥**」模式。

1. 把 `app_public_key.pem` 的内容粘进去
2. 保存后，页面会给你一段「**支付宝公钥**」—— **复制它**

> 🚨 **这里是整个配置里最容易错的一步：**
>
> | 名称 | 长什么样 | 用在哪 |
> | --- | --- | --- |
> | 应用公钥 | 你自己生成的 | **上传到平台**，不进配置文件 |
> | **支付宝公钥** | 平台给你的 | **配到 `ALIPAY_PUBLIC_KEY`** |
>
> 这两个都是一行长 base64，**长得几乎一样**。传错的后果是**所有验签失败**，
> 而报错只有「验签失败」四个字，完全指不到根因。
>
> 判据很简单：**配置文件里那一项的名字是「支付宝公钥」**，就不要放你自己生成的那个。

---

## 第四步：签约产品

开放平台控制台 → 你的应用 → **产品绑定**（或「能力列表」），分别签约：

| 要签的产品 | 用在哪 |
| --- | --- |
| **电脑网站支付** | 电脑上付款 |
| **手机网站支付** | 手机上付款 |
| **获取会员信息** | 顾客扫码一键登录 |

**个人实名账号即可签约，不需要企业主体。** 签约走线上流程、**需要审核**，
审核通过前对应的接口调用会报「无权限」。

> ⚠️ 审核时长**以控制台当前显示为准**，本文不写死 —— 它随账号类型和时段变化，
> 写一个数字进来只会误导。签约当天就看到结果、或者等几天，都有可能。
>
> 三个产品可以**一次都提交**。别一个一个来 —— 手机网站支付和电脑网站支付
> 少签任何一个，对应设备的付款就会失败。

### 还要启用「openid 配置管理」

开放平台控制台 → 应用 → **开发设置** → **openid 配置管理** → 启用。

**不启用的话，授权登录拿不到 `open_id`**，而本系统用的就是 `open_id`
（官方说 `user_id` 未来会逐步回收）。这一步不做，授权登录会用不了。

---

## 第五步：配置授权回调地址

同一个「开发设置」页里，有一项「**授权回调地址**」，填：

```
https://<你们的公网域名>/#/print
```

**必须和实际访问地址一字不差**（协议、域名、端口、路径、有没有 `#` 都要对上），
否则支付宝会拒绝回跳。

> ✅ **这里可以填内网地址**（开发期就是那么干的）。但生产用公网 HTTPS —— 见「开始之前」。
> 支付宝**不校验域名备案**，这点和微信完全不同（网上大量说法是错的）。

---

## 第六步：填进系统

配置走**环境变量**，**不进数据库** —— 私钥落库会跟着备份一起流出去。

在服务器的部署配置里（`.env`、docker-compose 的 `environment`、systemd 的
`Environment=`，看你用哪种）加：

```ini
ALIPAY_APP_ID=2021007xxxxxxxxx
ALIPAY_PRIVATE_KEY=<app_private_key_pkcs8.pem 的全部内容>
ALIPAY_PUBLIC_KEY=<第三步拿到的「支付宝公钥」>

# ⚠️ 生产【不要】设 ALIPAY_GATEWAY —— 留空就是正式网关。
#    那一项只在沙箱联调时指到 sandbox 地址。
ALIPAY_GATEWAY=

# 可选：只有非常规部署才需要（正常情况代码自己推断 opengauth 地址）
ALIPAY_AUTH_URL=
```

改完**重启服务**。

### 私钥怎么放进环境变量

多行 PEM 直接塞进 `environment:` 容易出问题。两种可行做法：

```bash
# 做法一：压成一行（PEM 的头尾也带着，代码认）
awk 'NF {printf "%s", $0} END {print ""}' app_private_key_pkcs8.pem

# 做法二：用 .env 文件（docker compose 会读）
#   把 PEM 原文粘进去即可 —— 代码会剥掉换行
```

### ✅ 检查点：启动日志

重启后在日志里找这一行（前缀是 `[config]`）：

```
[config] 支付宝: 生产  app_id=2021007xxxxxxxxx  gateway=https://openapi.alipay.com/gateway.do  authorize=https://openauth.alipay.com/oauth2/publicAppAuthorize.htm
```

**三个值都要看：**

| 字段 | 应当是 |
| --- | --- |
| 开头 | **`生产`**。显示 `沙箱` 说明 `ALIPAY_GATEWAY` 没清干净 |
| `gateway` | `https://openapi.alipay.com/gateway.do` |
| `authorize` | `https://openauth.alipay.com/...`（**不是** `alipaydev`） |

> ⚠️ **授权页主机和网关不是同一台**（`openauth` vs `openapi`），沙箱也是各自
> 一套。配错的代价是「用户手机上出现一个支付宝错误页，而我们这边毫无信号」——
> 所以这行日志把三个值都打出来。
>
> 🚫 日志里**只打 `app_id` 和网关，绝不打密钥**。`app_id` 本来就会出现在收银台
> URL 里，不是秘密；密钥一旦进日志就会跟着日志被备份、被贴进工单。

## 第七步：在管理界面开通计费

光配环境变量不够 —— 系统里还有开关：

1. **系统管理 → 取件终端**：确认「刷卡取件」是**关闭**的
   （计费与取件**互斥**，两个都开会出问题）
2. **系统管理 → 计费设置**：打开「**启用计费**」，并配好**价目表**
   （没配价目又没兜底价的话，开启会被拒 —— 那等于收款功能被静默关掉）
3. **确认支付宝真的出现了**：传个文件走到支付弹窗，看支付方式里有没有支付宝。

   > 判据是**能构建出渠道实例**（也就是第六步那三个环境变量齐全），
   > 不需要在界面上额外勾选任何东西。
   > 库里有个 `payment_methods` 设置项可以进一步限制只显示哪几种渠道，
   > 但它**默认是空的 = 不限制**，而且**管理界面里没有对应的 UI**——
   > 正常情况下不用管它。

### 站点地址（`site_base_url`）—— 生产建议填

**系统设置**里有「站点地址」。它决定两件事：

| 配了 | 没配 |
| --- | --- |
| `return_url` 用这个地址拼 | 从本次请求推断 |
| **会向支付宝发 `notify_url`（异步通知）** | **不发**，结算全靠主动查单 |

生产是公网 HTTPS，**建议填上**（形如 `https://<域名>`），这样：

- 回跳地址稳定，不依赖用户是怎么访问进来的
- **回调 + 主动查单双保险**，到账更快

> 本项目**不依赖**回调也能正常工作 —— 到账一律靠 `alipay.trade.query` 主动查
> （前端轮询顺带查 + 后台每 30 秒兜底）。回调只是让「付完几秒内界面就变」更快。
> 所以 `notify_url` 不需要公网可达**也能跑**；但既然生产本来就是公网，填上更好。

## 第八步：上线前检查清单

逐条打勾：

- [ ] 公网地址是 **HTTPS**（iOS 的硬要求）
- [ ] 开放平台里「授权回调地址」= 实际访问地址，**一字不差**
- [ ] 三个支付产品都**已审核通过**（电脑网站支付 / 手机网站支付 / 获取会员信息）
- [ ] 「**openid 配置管理**」已启用
- [ ] `ALIPAY_PRIVATE_KEY` 是**应用私钥**
- [ ] `ALIPAY_PUBLIC_KEY` 是**支付宝公钥**（不是应用公钥！）
- [ ] `ALIPAY_GATEWAY` **为空**
- [ ] 启动日志显示 **`生产`** + `openapi.alipay.com` + `openauth.alipay.com`
- [ ] 管理界面里「启用计费」已开、价目表已配
- [ ] 「站点地址」填成了公网地址
- [ ] 刷卡取件模式**关闭**
- [ ] `.env` / compose 文件**不在 Git 里**（私钥不能进版本库）

## 第九步：真机验证

**必须用真机、真钱走一遍**（金额设 0.01 元）。

### A. 付款

1. **手机**：登录 → 传文件 → 提交 → 支付弹窗里选支付宝 → 应当跳到支付宝收银台
   → 付款 → **自动回到网站的中间页**，显示「支付成功」
2. **电脑**：同一流程 → 收银台页面显示二维码 → 手机扫码付款 → 电脑上页面回跳
3. 到管理界面看那笔订单：状态应当是 `printed` 或 `printing`，金额对得上
4. **查一下钱**：登录支付宝商家后台，确认这笔真的到账了

### B. 退款

5. 在管理界面给那笔订单点「退款」→ 确认余额回来了，且订单上记了退款金额

### C. 一键登录

6. 手机上用**没登录过的浏览器**打开系统 → 点「支付宝登录」→ 授权 →
   应当自动回到系统且已登录

> ⚠️ 授权登录**必须在支付宝客户端内完成**（官方要求）。端外的流程见
> [alipay-login.md](alipay-login.md) 里「授权在支付宝里做，会话交回浏览器」那一节。

### D. 内网全链路（可选，但强烈建议）

在**项目目录的上一层**（跟 `fake-alipay-gateway.js` 放在一起）有
`verify-alipay.sh` —— 它用手写的假网关跑一遍完整链路，**不需要真商户资质**，
可以把「协议层的问题」和「资质/配置层的问题」分开：

```bash
cd <项目目录的上一层>
bash verify-alipay.sh
```

> 要在 **Git Bash** 里跑，不是 WSL。

## 第十步：换一个支付宝账号

**什么时候需要换**：开发期用的是某个人的支付宝账号，上线要换成部署方自己的
（个人账号或公司账号都行 —— 签约路径一样，见「开始之前」）。
也可能只是换个应用（比如开发应用和正式应用分开）。

**不管换成谁，动作都是一样的。按顺序做：**

| # | 做什么 | 为什么 |
| --- | --- | --- |
| 1 | 用**新账号**登录开放平台，**创建一个新应用** | 应用属于创建它的账号。已有应用**不能过户**，只能新建 |
| 2 | 新应用里**重新走**第二~五步（生成新密钥、上传应用公钥、签约三个产品、配回调地址） | 密钥和签约都跟着应用走，不能沿用旧的 |
| 3 | 回调地址填**生产的公网 HTTPS 地址** | 这一步不能拖到以后 —— 「一个应用只能配一个地址」，填错回跳全废 |
| 4 | 改服务器上的 `ALIPAY_APP_ID` / `ALIPAY_PRIVATE_KEY` / `ALIPAY_PUBLIC_KEY` 为**新应用**的 | 三样都是新应用的，**必须成套换**，混用会验签失败 |
| 5 | 确认 `ALIPAY_GATEWAY` 为空 | 开发期如果指过沙箱，这里必须清掉 |
| 6 | 重启服务，看启动日志确认是**新 AppID** + **生产**网关 | 日志就是为这个场景打的 |
| 7 | 按第八、九步走一遍检查清单和真机验证 | |

> 🚨 **第 4 步必须成套换。** 只换 `APP_ID` 而留着旧私钥（或反过来），表现是
> **所有接口都报验签失败** —— 而那句话不告诉你到底是哪一项配错了。
> 换的时候三样一起换，换完立刻看启动日志。

> ⚠️ 换之前先确认新账号那边的**三个产品都审核通过**了。别等到上线当天才发现
> 还没过 —— 审核时长以控制台当前显示为准。

### 换的时候老数据怎么办

- **余额、订单、流水都不会丢** —— 它们在我们自己的库里，跟支付宝的应用无关。
- **已经用旧应用付过款的订单**：退款走的是 `alipay.trade.refund`，**会打到旧应用的
  商户号**。所以**换应用之前，先把还用旧账号的未结清订单处理完**（该打的打、
  该退的退）。换完之后再冒出旧应用的订单，退款可能会失败。

## 排障

### 启动日志显示「未配置（支付方式里不会出现支付宝）」

三个环境变量没齐。检查 `ALIPAY_APP_ID` / `ALIPAY_PRIVATE_KEY` / `ALIPAY_PUBLIC_KEY`
是不是都非空 —— **任意一个为空就整体不可用**，且前端不会显示支付宝选项。

### 所有接口都报「验签失败」

按可能性排序：

| 原因 | 怎么确认 |
| --- | --- |
| **`ALIPAY_PUBLIC_KEY` 填成了「应用公钥」** | 最常见。回开放平台重新复制「**支付宝公钥**」 |
| 换应用时三样没成套换 | 启动日志里的 `app_id` 和你改的是不是同一个应用 |
| 私钥带了平台没认的格式 | 代码认 PEM / 裸 base64 / 带换行三种；把你的私钥喂给 `openssl rsa -check` 看能不能解析 |
| 用的是沙箱密钥但网关指向生产（或反过来） | 日志里的「生产/沙箱」标记得对 |

### 手机上跳到支付宝后白屏

**九成是 http**。iOS 的支付宝不加载明文 —— 回跳地址、站点地址都必须是 HTTPS。

其次：回调地址里带 `#` 在 iOS 上可能出 bug，换成不带 `#` 的路径试试。

### 电脑上能用、手机上不能用（或反过来）

两个支付产品**要分别签约**。只签了「电脑网站支付」的话，手机上会失败，
反之亦然。去开放平台确认两个都签了。

### 顾客点「支付宝登录」提示「请在支付宝客户端打开链接」

这是**正常的**：官方要求授权必须在支付宝客户端内完成。系统的设计是
「授权在支付宝里做，会话交回浏览器」，端外会先唤起 App。
流程见 [alipay-login.md](alipay-login.md)。

### 付款成功了但订单没变

本项目**不依赖回调**也能结算 —— 到账靠主动查单（前端轮询顺带查 + 后台每 30 秒兜底）。

- 等十几秒看看会不会自己变
- 不变的话，点一下「我已支付」按钮（它是认证过的人类点击，**不加节流**）
- 还是不变 → 看服务器日志里 `alipay.trade.query` 的返回

### 需要改回调地址 / 换域名

- 开放平台里改「授权回调地址」（**改完要重新登录一次才生效**）
- 系统设置里的「站点地址」跟着改
- **不用重启服务**（站点地址存在库里，读的时候是实时的）
