# 刷卡取件终端部署手册

**面向正式环境。从第一条做到最后一条，中间不要跳步。**

做完之后的状态：员工在电脑上提交打印 → 走到打印机旁刷工牌 → 纸打出来。

> 原理与设计取舍在 [pull-printing.md](pull-printing.md)，那份是给改代码的人看的。
> 本文只讲怎么做。

---

## 开始之前

### 需要准备的东西

| 东西                 | 说明                                                                         |
| -------------------- | ---------------------------------------------------------------------------- |
| **读卡器**     | 推荐**ACR122U**（PC/SC，USB 插上就用）。**买之前先看下面的验证** |
| **一台小机器** | 放在打印机旁边，常开。树莓派 / 迷你主机 / 旧笔记本都行                       |
| **网络**       | 这台机器要能访问服务器的地址（跟员工电脑访问系统是一回事）                   |
| **服务器**     | 已经在跑 cups-web，**且是带取件功能的版本**（第一步会验）              |
| **另一台电脑** | 管理员的电脑。用来跑浏览器管理界面；如果还要做绑卡终端，它也得能插读卡器     |

下面的步骤里会出现三类机器，先分清：

```
【服务器】     跑 cups-web 的那台
【终端机器】   打印机旁边那台（要装 kiosk.py）
【管理端】     你打开浏览器的那台电脑
```

### 🚨 买读卡器之前必须先验卡型

**拿一张真工牌，放到候选读卡器上读一次。** 企业工牌常见两种，**互相读不出来**：

| 卡的类型                  | 频率      | 怎么快速分辨                 |
| ------------------------- | --------- | ---------------------------- |
| IC 卡（Mifare / DESFire） | 13.56 MHz | 手机贴上去（NFC）有反应      |
| ID 卡（EM4100）           | 125 kHz   | 手机 NFC**完全没反应** |

**ACR122U 是 13.56 MHz 的，读不出 125 kHz 的 ID 卡。** 这一步不做就批量采购，
钱和时间都白花。

另外，读出来的是**卡片的 UID**（形如 `04A23B1C`），**跟卡面上印的数字通常不一样** ——
这是正常的，不是读错了。

## 第一步：在服务器上确认版本

在【服务器】上：

```bash
cd <cups-web 项目目录>
make all
# 然后按你平时的部署方式重启后端
```

**在【管理端】上验证新版本已经跑起来**（把地址换成你们服务器的）：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://192.168.1.22:1180/api/version
curl -s -X POST http://192.168.1.22:1180/api/kiosk/ping \
  -H 'Content-Type: application/json' -d '{"token":"x"}'
```

- 第一条返回 `200` → 服务在、地址对
- 第二条返回 `{"status":"unknown_terminal"}` → **新版本已经在跑** ✅
- 第二条返回 `404` → **服务端还是旧版本**，回去重新部署，别往下走

> ⚠️ 这个地址就是后面配置文件里的 `server`。**先在这里确定下来**，
> 别等到写配置时再猜。

---

## 第二步：开通取件模式

用【管理端】的浏览器：

1. **系统管理 → 计费设置**：确认**计费是关闭的**。
   计费与取件**互斥**，两个都开会出问题。
2. **系统管理 → 取件终端**：打开「**启用刷卡取件**」。
   - 报错说和访客模式冲突 → 先去「系统设置」关掉访客模式。
   - 顺便设「**取件时限**」（默认 72 小时）：员工超过这个时间没来取，
     任务作废、文件被清理。

---

## 第三步：创建终端，拿 token

在这一页（**系统管理 → 取件终端**）点「**新增终端**」。要建**几种**看你的需要：

### 3.1 取件终端（放在打印机旁边的，必须建）

- **不勾**「仅用于绑卡」
- **对应打印机**：选这台终端旁边的那台打印机
- 名称随便填，但要**填得让你自己认得出**（比如「3楼东侧」）——
  现场排障时全靠它定位

创建后弹出的「**配置指引**」里有一串 token，**复制下来**。

> 同一台打印机只建一个终端。多台打印机就建多个，各自一个 token。

### 3.2 绑卡终端（放管理员工位的，建议建）

- **勾上**「**仅用于绑卡（不负责取件）**」
- 不用选打印机（绑卡只需要读一次卡）

有了它，**绑卡时读卡器就在你手边，不用走到打印机那边去** ——
UID 是芯片固化的，读卡器插在哪台机器上读出来都是同一个值。

> 3.1 和 3.2 装的是**同一份程序**，只是配置文件里的 token 不同。
> 两者互相独立：只要绑卡就在工位上做的话，3.1 也可以先不建；
> 反过来没有取件终端的话，整个取件功能就没法用。

---

## 第四步：把 kiosk.py 复制到终端机器

下面以【终端机器】是树莓派 / Ubuntu 为例。

### 4.1 先确认能连上那台机器

```bash
# 在【管理端】上试
ssh <终端机器的用户名>@<终端机器IP>
```

> 树莓派默认**没开 SSH**。要在它上面执行 `sudo raspi-config`
> → Interface Options → SSH → 启用。

连不上就先解决这个 —— 后面全都要靠它。

### 4.2 复制过去

```bash
# 在【管理端】，cups-web 项目目录下
scp scripts/kiosk/kiosk.py <用户名>@<终端机器IP>:/tmp/kiosk.py

# 顺带把安装脚本和 systemd 单元也拷过去（可选，第九步用得上）
scp scripts/kiosk/install.sh scripts/kiosk/cups-kiosk.service <用户名>@<终端机器IP>:/tmp/
```

---

## 第五步：装依赖

在【终端机器】上：

```bash
sudo apt update
sudo apt install -y pcscd python3-pyscard python3-requests
sudo systemctl enable --now pcscd
```

### ✅ 检查点：读卡器通了没

```bash
pcsc_scan
```

刷一张卡，屏幕上应当出现类似 `card 04 A2 3B 1C` 的字样。

- **看到了** → 按 `Ctrl+C` **退出**，继续下一步
- **看不到** → 先停下来查读卡器本身：换 USB 口、换线、确认卡型（见「开始之前」）

> ⚠️ **`pcsc_scan` 用完必须关掉。** 它会一直占着卡片，和 `kiosk.py` 抢，
> 现象是满屏的 `Card was reset`。

---

## 第六步：放程序、写配置

在【终端机器】上：

### 6.1 放程序

```bash
sudo cp /tmp/kiosk.py /usr/local/bin/cups-kiosk
sudo chmod +x /usr/local/bin/cups-kiosk
```

### 6.2 先验一次读卡器

**这一步不需要 token，也不需要配置文件**，专门用来把「读卡器问题」和
「配置问题」分开：

```bash
sudo /usr/local/bin/cups-kiosk --read
```

刷一张卡，应当打出：

```
  UID = 04A23B1C
```

**看到了就记住这个值** —— 第九步绑卡要用。

没打出来时，对照着看是哪一种：

| 输出                                           | 含义                                                                         |
| ---------------------------------------------- | ---------------------------------------------------------------------------- |
| `SW=xxxx`（不是 9000）                       | **卡型**不吃这条取 UID 命令。换一张卡试试；都这样就是读卡器/卡型不匹配 |
| `这次没读全（卡多半是在读的过程中被拿开了）` | 再刷一次。每次都这样 → 卡没放稳，或者有东西在抢卡                           |
| `没有找到任何读卡器`                         | 第五步的依赖没装好，或读卡器没插稳                                           |
| **已经有一个 cups-kiosk 在运行了**       | 装过的服务还在跑，两个进程会抢卡：`sudo systemctl stop cups-kiosk`         |
| 读不了配置文件                                 | 配置文件按建议设成了 600（只有 root 能读），加`sudo`                       |

### 6.3 写配置

把**第三步复制的那串 token**填进去，`server` 填**第一步验过的那个地址**：

```bash
sudo tee /etc/cups-kiosk.conf > /dev/null <<'EOF'
server = http://部署的打印服务器IP地址 : 端口
token  = 这里粘贴第三步复制的 token
EOF
sudo chmod 600 /etc/cups-kiosk.conf
```

> ⚠️ **把上面两行的值换成你自己的**，别照抄。
> `server` 抄错、或者 token 带上了首尾空格，是后面最常见的两种失败。

> ⚠️ `600` 意味着**只有 root 能读**（token 等同于密码），所以后面启动都要 `sudo`。

---

## 第七步：启动并自检

```bash
sudo /usr/local/bin/cups-kiosk
```

它先自检，再进入等待。**正确输出长这样**：

```
读卡器：ACS ACR122U PICC Interface 0
服务器：http://192.168.1.22:1180
终端：  YMCOTG6T…
自检中…
  ✅ 服务器、token、地址都对
  ✅ 读卡器已就绪（ACS ACR122U PICC Interface 0）

等待刷卡…（Ctrl+C 退出）
```

### 自检没过时，照着改

| 自检输出                                | 怎么修                                                              |
| --------------------------------------- | ------------------------------------------------------------------- |
| `❌ 连不上服务器`                     | `server` 地址/端口写错了，或这台机器到服务器不通（`ping` 一下） |
| `❌ 服务器上还没有取件接口`           | 服务端还是旧版本 → 回第一步                                        |
| `❌ token 不对：服务器不认识这个终端` | token 抄错了（多半带了空格）→ 回第三步重抄                         |
| `❌ 这个终端在管理界面里被停用了`     | 去「取件终端」页把它启用                                            |
| 读卡器那一行都没打出来                  | 第五步的依赖没装好，或者读卡器没插好                                |

### ✅ 检查点：刷一次卡

先**随便刷一张卡**（哪怕还没绑），应当看到：

```
读到卡：04A23B1C
  ❌ 工牌未登记，请联系管理员绑卡
```

**看到「工牌未登记」就说明整条链路都通了** —— 读卡器、网络、token 全对，
只差绑卡这一步。按 `Ctrl+C` 退出，做第八步。

## 第八步：设为开机自启

手工验证通过之后，才能装成服务。在【终端机器】上：

```bash
# 如果前面把 install.sh 和 .service 拷过来了，直接用它：
sudo /tmp/install.sh /tmp/kiosk.py

# 或者手工装：
sudo tee /etc/systemd/system/cups-kiosk.service > /dev/null <<'EOF'
[Unit]
Description=CUPS Web 刷卡取件终端
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/local/bin/cups-kiosk -config /etc/cups-kiosk.conf
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal
SyslogIdentifier=cups-kiosk

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now cups-kiosk
systemctl status cups-kiosk           # 看它活着没
journalctl -u cups-kiosk -n 30        # 看日志
```

> ⚠️ **装成服务之后，就不能再手工跑 `kiosk.py` 了** —— 两个进程会抢同一张卡。
> 手工验证前先 `sudo systemctl stop cups-kiosk`。

**最后重启一次终端机器，确认服务能自己起来**（这一步别省，自启没配好的话
下次断电就再也起不来了）：

```bash
sudo reboot
# 等它起来之后，在【管理端】看「取件终端」页的「最近上线」有没有更新
```

## 第九步：绑定员工的 IC 卡

**前提**：第八步做完。

三种方式，按场景选：

### 方式一：在自己工位上刷卡（推荐）

需要**先做第三步的 3.2**（建一台「仅用于绑卡」的终端），并且在
【管理端】那台电脑上把程序也跑起来（第四~八步同样流程，token 用 3.2 那串）。

1. 确认管理端那台的 `cups-kiosk` 正在跑，并且**读卡器插在它上面**
2. 管理界面 → **系统管理 → 用户管理**
3. 找到要绑的账号，点那一行的「**绑卡**」
4. 点「**开始等待刷卡**」—— 窗口 2 分钟内有效
5. **在自己桌上的读卡器上刷一下要绑的卡**
6. 界面会自动变成「**绑定成功**」并显示卡号

> ⚠️ 窗口开着的那 2 分钟里，别在打印机那边刷卡（那张卡会被绑给这里选的人）。
> 真发生了就点「解绑」重来。

### 方式二：到打印机旁的终端刷卡

管理员电脑不方便插读卡器时用。流程完全一样，第 5 步改成走到打印机那边刷。

### 方式三：手抄 UID（批量发卡最快）

一次绑一批人时用这条：

1. 在任意一台有读卡器的机器上跑 `sudo cups-kiosk --read`
2. 连着刷完这一批，把 UID 都记下来
3. 回到管理界面，逐个「绑卡」→ **把 UID 粘进输入框** → 确认绑定

> 大小写、以及 UID 中间可能带的冒号（`04:A2:3B:1C`）或连字符，服务器会
> **自动统一** —— 照原样贴进去就行，不用自己整理。

### 换卡 / 解绑

- **换卡**：直接重新绑一次，覆盖旧的
- **解绑**：绑卡对话框里有「解绑」，解绑后那张卡可以绑给别人
- **提示「这张卡已经绑定给 XXX 了」**：那张卡在别人名下，先去那边解绑

## 第十步：验收

**装完必须自己走一遍，别等员工来发现。** 在【管理端】用**绑过卡的员工账号**登录：

| # | 操作                 | 应当看到                                                                          |
| - | -------------------- | --------------------------------------------------------------------------------- |
| 1 | 在线打印 → 选打印机 | 下拉里**只有配了终端的那台**                                                |
| 2 | 传文件 → 提交       | 跳到中间页，大字写着「**请到这台打印机前刷卡取件**」+ 打印机名字 + 过期时间 |
| 3 | 看打印机             | **纸这时候不应该出来** ⚠️                                                 |
| 4 | 走到打印机旁刷卡     | 纸出来；终端日志打出「✅ 已开始打印」                                             |
| 5 | 回电脑看「打印记录」 | 顶部「待取件」里那条**没了**                                                |

**第 3 步是最关键的一条判据** —— 纸提前出来了说明取件模式没生效，回第二步。

其余几条的失败含义：

| 现象                                     | 原因                                                                 |
| ---------------------------------------- | -------------------------------------------------------------------- |
| 下拉里一台都没有                         | 那台打印机没建终端（第三步 3.1），或者终端被停用                     |
| 刷卡响「工牌未登记」                     | 卡没绑上，或绑的 UID 和刷出来的对不上（回第九步）                    |
| 刷卡响「这台打印机上没有你的待取件任务」 | 任务提交到了**另一台**打印机。取件是**锁定打印机**的     |
| 刷卡响「打印机当前不可用」               | 服务器探测到打印机离线。**这时任务不会丢**，打印机好了再刷一次 |

## 第十一步：声音反馈（建议做）

**终端没有屏幕，声音是员工唯一能知道「刷上没刷上」的通道。**
不做的话，员工刷完只能站在那儿猜，然后来问你。

`kiosk.py` **默认不出声** —— 因为「怎么响」取决于现场接了什么硬件。

### 接一个蜂鸣器（树莓派最简单）

先验证能响（以 GPIO 17 为例）：

```bash
echo 17 | sudo tee /sys/class/gpio/export
echo out | sudo tee /sys/class/gpio/gpio17/direction
echo 1 | sudo tee /sys/class/gpio/gpio17/value   # 响
sleep 1
echo 0 | sudo tee /sys/class/gpio/gpio17/value   # 停
```

响了就写成脚本：

```bash
sudo tee /usr/local/bin/kiosk-beep > /dev/null <<'EOF'
#!/bin/sh
# 按 $KIOSK_STATUS 响不同的声。引脚号按实际接线改。
PIN=17
beep() {
  echo 1 > /sys/class/gpio/gpio$PIN/value
  sleep "$1"
  echo 0 > /sys/class/gpio/gpio$PIN/value
}
case "$KIOSK_STATUS" in
  released)               beep 0.6 ;;                       # 成功：一长声
  partial|failed)         beep 0.6; sleep 0.12; beep 0.6 ;;  # 打印失败：两长声
  unreachable|old_server) beep 0.6; sleep 0.12; beep 0.6; sleep 0.12; beep 0.6 ;;
  bad_swipe)              exit 0 ;;                          # 误触：不响
  *)                      beep 0.08; sleep 0.12; beep 0.08; sleep 0.12; beep 0.08 ;;
esac
EOF
sudo chmod +x /usr/local/bin/kiosk-beep
```

在 `/etc/cups-kiosk.conf` 里加一行，然后重启服务：

```bash
sudo sed -i '$a beep_cmd = /usr/local/bin/kiosk-beep' /etc/cups-kiosk.conf
sudo systemctl restart cups-kiosk
```

> 用「长响 / 短响」分成两组：**长响都是打印相关的成败**，
> **短响都是这次刷卡没能进行**。次数太多人分不清，分两组是有意的。

### 打印一张声码卡

**贴一张在读卡器旁边。** 不贴的话没人记得住响几声是什么意思。

| 声音      | 含义                           |
| --------- | ------------------------------ |
| 长响 1 声 | ✅ 任务已开始打印              |
| 长响 2 声 | 部分任务失败，找管理员         |
| 长响 3 声 | 全部失败，找管理员             |
| 长响 4 声 | 连不上服务器，找管理员         |
| 短响 2 声 | 这台打印机上没有你的待取件任务 |
| 短响 3 声 | 工牌未登记，找管理员绑卡       |
| 短响 4 声 | 打印机当前不可用，稍后再试     |
| 短响 5 声 | 终端未注册或已停用，找管理员   |
| 短响 6 声 | 刷得太频繁，等一下             |
| 无声      | 空刷卡（误触），不用管         |

## 附 A：日常使用

- **员工**：提交 → 看到中间页 → 去打印机刷卡 → 取纸
- **没取走的任务**在「个人中心 → 打印记录」顶部的「**待取件**」里，
  可以撤销，也能看到什么时候过期
- **取件锁定打印机**：在哪台提交就只能在哪台取

给管理员的两句提醒：

1. **绑卡窗口是全局唯一的。** 开着的时候别人开不了新的。关掉对话框会自动取消；
   忘了关的话 2 分钟后过期。
2. **取件模式下不要用定时打印。** 它会让保密文档无人值守地躺在出纸口 ——
   而那正是拉式打印要消灭的场景。所以它被**显式拒绝**了，任务会报失败，
   原因写在任务详情里。

## 附 B：排障

### 刷卡完全没反应

按顺序查，**别跳步**：

```bash
# ① 服务活着吗
systemctl status cups-kiosk
journalctl -u cups-kiosk -n 50

# ② 读卡器本身还好吗（先停服务，否则两边抢设备）
sudo systemctl stop cups-kiosk
pcsc_scan                              # 刷卡，看有没有反应；看完 Ctrl+C 关掉
sudo /usr/local/bin/cups-kiosk --read  # 刷卡，看能不能打出 UID

# ③ 服务端通吗
curl -s -o /dev/null -w '%{http_code}\n' http://<服务器地址>/api/version

# ④ 看自检说什么
sudo /usr/local/bin/cups-kiosk

# 恢复
sudo systemctl start cups-kiosk
```

### 满屏 `Card was reset`

PC/SC 在说「读的过程中卡被打断了」。**通常不是读卡器坏了**：

| 可能                 | 怎么修                                                                          |
| -------------------- | ------------------------------------------------------------------------------- |
| 两个进程抢同一张卡   | 最常见：服务在跑，又手工开了个`--read`。先 `sudo systemctl stop cups-kiosk` |
| `pcsc_scan` 还开着 | `Ctrl+C` 关掉                                                                 |
| 卡拿得太快           | 出现一两次正常；每次都这样 → 卡没放稳                                          |
| USB 接触不良         | 换 USB 口，别用延长线 / 劣质 HUB                                                |

### 「工牌未登记」但明明绑过

九成是**读出来的 UID 和绑的那串对不上**：

```bash
sudo /usr/local/bin/cups-kiosk --read
```

拿去和管理界面「工牌」列显示的值逐位对一下。
最常见原因：**绑卡时用的是另一个型号的读卡器**（不同型号读同一张卡可能给出
不同的值）。统一型号之后重新绑一遍。

### 「打印机当前不可用」

服务器**直连探测**到打印机离线（不是 cupsd 说的状态，那个不可信）。
这时**不会改任何数据** —— 任务原样留着，打印机好了再刷一次就行。

## 附 C：升级 / 换服务器

- **升级服务端**：终端**不用动**。服务重启期间终端会报「连不上服务器」，
  恢复后自己就好
- **换服务器地址或 token**：改 `/etc/cups-kiosk.conf` 那两行，然后
  `sudo systemctl restart cups-kiosk`
- **升级终端程序**：重新 `scp` 一次，覆盖 `/usr/local/bin/cups-kiosk`，
  然后 `sudo systemctl restart cups-kiosk`

## 附 D：状态码对照（配 `beep_cmd` 时用）

`$KIOSK_STATUS` 会拿到下面这些值：

| 状态码                   | 含义                                           |
| ------------------------ | ---------------------------------------------- |
| `released`             | ✅ 任务已开始打印                              |
| `partial` / `failed` | 部分 / 全部任务打印失败                        |
| `no_jobs`              | 这台打印机上没有你的待取件任务                 |
| `card_unbound`         | 工牌未登记                                     |
| `printer_unavailable`  | 打印机当前不可用                               |
| `unknown_terminal`     | 终端未注册（token 错）                         |
| `terminal_disabled`    | 终端已停用                                     |
| `rate_limited`         | 刷得太频繁                                     |
| `unreachable`          | 连不上服务器                                   |
| `old_server`           | 服务器上没有取件接口（旧版本）                 |
| `bound`                | ✅ 工牌绑定成功                                |
| `bind_taken`           | 这张卡已绑给别人                               |
| `bind_failed`          | 绑定失败                                       |
| `bind_idle`            | 绑卡专用终端：请先在管理界面点「开始等待刷卡」 |
| `bad_swipe`            | 空刷卡（误触）                                 |
